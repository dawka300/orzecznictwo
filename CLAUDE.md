# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Shared skeleton for projects that download court judgments into MariaDB and run unattended on shared hosting (seohost, Python, cron). Projects: `nsa/` (Polish administrative courts, CBOSA) and `etpc/` (European Court of Human Rights, HUDOC). Grew out of the local `orzeczenia_SAOS` project (SAOS in Postgres); this repo is MariaDB-only, vectors go to a separate dedicated store later. README.md explains the layout; the root and each project's `notepad.md` hold the state and next steps (local working notes, gitignored since 2026-10-21 - not on GitHub).

## Running

Readable command cheat sheet for the user (Polish, by topic: Docker, fetching, processing, vectors, search/RAG, web, tests): `komendy.md` in the repo root (tracked; first full copy-paste commands, then every command and flag explained). Keep it in sync when adding or changing CLI commands or flags.

- Python: there is no local Python (no `.venv`); everything runs in a one-off container of the `www` image (Python 3.13, repo mounted at `/app`, `ETPC_*`/`NSA_*` env from compose pointing at `db`, `qdrant` and LM Studio on `host.docker.internal:1234`): `docker compose run --rm --no-deps www python -m <project> <command>`. `run --rm` survives `docker compose restart www` and doesn't take port 8080. **Always `--no-deps`**: without it compose also brings up `db`, and after any change to the `db` service in `docker-compose.yml` it recreates the database container (SIGKILL, crash recovery, every running pass and connection cut - happened on 2026-10-20); `db` and `qdrant` run anyway (Docker Desktop starts them). logs go to `logs/www` (`-e ETPC_LOG_DIR=logs` for another dir). The image also has curl and Playwright with Chromium, so the whole HUDOC transport chain (requests -> curl -> playwright, `ETPC_TRANSPORT`) works there. After changing `docker/www.Dockerfile` or `requirements.txt`: `docker compose build www`. Code must stay compatible with **Python 3.9+** (hosting may be older): `from __future__ import annotations` in modules with type hints, no `match`, no `datetime.UTC` (use `timezone.utc`), no 3.10+ stdlib. Ruff targets py39 (`pyproject.toml`).
- Dependencies stay minimal and pure Python (`requests`, `PyMySQL`): no compiled packages on the hosting path. Dev-only tools go in `requirements-dev.txt`.
- `docker compose up -d`: local MariaDB 10.11 on 127.0.0.1:3306 (user/password `szkielet`, root `root`), databases `nsa`, `etpc`, `szkielet_test`, `teczki` (the case folder: user documents, `judgments_core/library.py`), `trening` (documents for training our models, `judgments_core/training.py` `TrainingLibrary(Library)`: tab „Trening” at `/trening` and JSONL export, only with `APP_ENV=dev`) (created by `docker/mariadb-init.sql` on first volume creation only); Qdrant 1.19 (vector store, local only) REST on 127.0.0.1:6333.
- Commands (from the repo root, each prefixed with `docker compose run --rm --no-deps www`): `python -m nsa migracje | pobierz [--limit N] [--na-sucho] [--od-poczatku] [--budzet S] | stan | kopia`, same for `etpc`; `python -m portal` = all search pages on http://127.0.0.1:8080 (`/etpc/`, `/nsa/`, each with its search and statistics; `/` lists them; old unprefixed ETPC addresses redirect to `/etpc/`; `judgments_core.web.Portal` + `portal/__main__.py`, outside the core because it imports projects); locally it runs as the compose service `www` (restarts with docker, mounts the repo: `docker compose restart www` after code changes; a manual server would collide on port 8080). `python -m etpc|nsa www [--port]` still serves one project alone. `python -m etpc|nsa wektory` = embeddings into Qdrant (collections `etpc_<model>`, `nsa_<model>`). Vectors are chosen the same way everywhere except the bulk `wektory` (only LM Studio, `http`, never the CPU; the bulk is usually computed on CUDA elsewhere, e.g. Vast, as packages) - pages, MCP, document tabs, case folder, training: `<PREFIX>_QUERY_EMBEDDERS` default `auto` = `AutoEmbedder` in `judgments_core/embeddings.py`: LM Studio when it answers and has `EMBED_MODEL` (bge-m3) loaded, else bge-m3 via sentence-transformers on the CPU in the process (checked again every 60 s); so everything works without LM Studio. `python -m etpc|nsa mcp` = MCP server over stdio (tools `szukaj`, `fragmenty`, `orzeczenie`, `podobne`; registered in `.mcp.json` as `docker compose run --rm --no-deps -T www python -m etpc|nsa mcp`, so Docker must be running; `mcp` is in the image; Python 3.10+, local only). `python -m etpc|nsa fragmenty "pytanie"` = RAG context (best passages packed into a limit, `judgments_core/rag.py` `Retriever`); `python -m etpc|nsa formulki` = sentences repeated in many judgments (`<project>/formulki.txt`; with the patterns in `<project>/formulas.py`, children of `judgments_core/boilerplate.py` `FormulaCorpus`), dropped in every document tab (`judgments_core/documents.py` `DocumentPages`: analysis, comparison, case analysis, case folder, research). `python -m etpc|nsa tematy` = BERTopic topics over the Qdrant vectors (`judgments_core/topics.py` `TopicModel` -> `etpc/topics.py`, `nsa/topics.py`; NSA: level A in float16 memory-mapped files (`on_disk`), level B only a slice, `chunk_filter`). `python -m etpc|nsa ocen` = retrieval quality on golden questions `<project>/pytania.json`. `python -m etpc|nsa podobne-do <file|->` = judgments closest to a whole text (`Retriever.like_text`: the text is chunked by the project's chunker, each chunk searches the vectors, rankings fused by rrf; `--wynik` filters by outcome, since opposite rulings are as close in meaning). NSA vectors have two levels (`nsa/embed.py` `full_chunks`): full chunks for resolutions, judgments with a thesis or published and NSA judgments; one summary vector (`NsaChunker.summary`) for the rest. `python -m etpc|nsa zapytaj "pytanie"` = RAG answer by a local chat model (LM Studio, `<PREFIX>_CHAT_*`). `python -m <project> paczki` / `paczka-import <name>` = embedding packages computed on other machines (`judgments_core/packages.py`; colleagues run `docker/licz/` with an NVIDIA GPU). `kopia` (and, with `<PREFIX>_BACKUP_DIR` set, every pobierz/przetworz that changed something) dumps the DB to `<backup_dir>/<project>-<UTC YYYYMMDD-HHMMSS>.sql.gz`, keeping the newest 3 (`judgments_core/backup.py` `prune`) (in the container with `mariadb-dump --skip-ssl` from the image, `<PREFIX>_DUMP_COMMAND` set in compose over the `docker exec` one in `.env`); locally ETPC goes to `etpc/database/` (gitignored). Shared CLI in `judgments_core/cli.py`; a project's `__main__.py` only builds a `Project`. NSA `pobierz` = `CbosaSource` (`nsa/source.py`): CBOSA judgment pages `/doc/<ID>` for the ids in the files under `nsa/database/cbosa-id/` (no cursor; skips ids already in `raw_records` source `cbosa`; min 3 s pause); pages are read into the JuDDGES row shape (`nsa/cbosa.py`) so `parse_judgment` and the tables are shared; `NsaDeriver` derives JuDDGES then CBOSA (CBOSA wins). The ids come from the user's tool `narzedzia/cbosa_id.py` (or the Postman collection), which uses the CBOSA search that robots.txt disallows - keep that out of the project code.
- Tests: `docker compose run --rm --no-deps www python -m pytest` (~4 min; the pyarrow test is skipped, pyarrow isn't in the image). Lint: `docker compose run --rm --no-deps www sh -c "ruff format . && ruff check ."` (pytest and ruff are in the image; `EXE002` ignored because the Windows mount makes every file look executable). DB tests use `TEST_DB_DSN` (set in compose to `db:3306/szkielet_test`), drop all its tables, and are skipped when MariaDB isn't running. Never point `TEST_DB_DSN` at a real database.
- Settings: `judgments_core/settings.py`, env vars `PREFIX_FIELD` (`NSA_DB_DSN`, `ETPC_PAUSE_S`, ...), from the environment or the repo-root `.env` (path is fixed, not cwd, because cron starts elsewhere). Empty DSN = local compose DB named after the project. `APP_ENV=dev|prod` (no prefix, default prod) = environment: in `.env` it also picks the compose profile (`COMPOSE_FILE=docker-compose.yml;docker-compose.${APP_ENV:-prod}.yml`: dev = 64 GB override, prod = 32 GB user profile) and reaches `www`; dev-only features check `settings.dev`.

## Design rules

- **Raw first:** sources yield `RawRecord`s (JSON/HTML text as received) into `raw_records`; project tables/DTOs are derived from them by a parser, so parser changes never need a re-download. `changed_at` moves only when the body's sha256 changes.
- **Resumable:** `Importer` saves each page's records and the source's cursor in one transaction (`MariaDbStore.save_page`). The cursor is an opaque string the source defines. A pass may be killed anytime and the next resumes.
- **Cron, not a daemon:** each pass stops after `--budzet`/`*_TIME_BUDGET_S` seconds; `MariaDbStore.lock` (`GET_LOCK`) makes an overlapping pass exit with code 0.
- **Be polite to sources:** keep `PoliteClient`'s pause and backoff; set a contact in `*_USER_AGENT`.
- All MariaDB SQL of the core is in `judgments_core/db.py`. MariaDB, not MySQL 8: no `INSERT ... AS new` (use `VALUES(col)`), check features against the hosting's MariaDB version.
- `judgments_core` must not import from projects; projects import the core.
- **Core = common parent, projects = children.** When a project needs a core class to behave differently (another database, another save step, other paging ...), it gets a subclass in its own package (e.g. `nsa/importer.py: class NsaImporter(Importer)`, overriding only what changes) and its `__main__`/`Project` uses that child. Never put one project's case into a core file (no `if project == ...`); change the core only for what is common to all, and then keep every project working. `Project` takes the project's classes: `source`, `importer`, `deriver`, `embed_job`, `web`, `mcp`, `retriever` (children of `Source`, `Importer`, `Deriver`, `EmbedJob`, `WebApp`, `McpServer`, `Retriever`), plus `transports` (strategy chain of `judgments_core/transport.py`). Parents in the core: Transport, Embedder, Source, Importer, Parser, TableWriter, Deriver, Chunker, EmbedJob, SemanticSearch, Retriever, WebApp, McpServer (map in the root `notepad.md`).

## Schema changes

- Core tables: `judgments_core/migrations/NNN_*.sql`; project tables: `<project>/migrations/NNN_*.sql`. Applied by `python -m <project> migracje`, recorded in `schema_migrations` as `core/001_core.sql`, `nsa/001_...`. Never edit an applied migration; add a new one.
- MariaDB commits each DDL statement immediately: a migration failing halfway stays half-applied. Keep migrations small and re-runnable (`IF NOT EXISTS`). Statements are split on `;` at line ends, so no procedures/triggers in migration files.
- Tables: `ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci`; indexed VARCHAR max 191. DATETIME columns hold UTC.

## Conventions

- Code identifiers and docstrings are English. CLI commands and flags (`pobierz`, `--na-sucho`, ...), help text, log/printed messages and comments are Polish; flags map to English `args.*` via `dest=`.
